Hello-Agents 第二章学习笔记：智能体发展史

发表于 2026-11-05 更新于 2026-11-06 分类于 AI Agent 阅读次数：
学习 Datawhale Hello-Agents 第二章后，整理从符号主义、专家系统、神经网络到大语言模型和现代 Agent 的发展脉络，方便后续复习。

第一章让我理解了 Agent 是什么，第二章让我开始理解：今天的 Agent 并不是突然出现的，它是人工智能几十年里“知识表示、学习、决策和行动”几条路线逐渐汇合的结果。

一、为什么要学习发展史

只记住“现在流行什么框架”，很容易把技术名词和产品营销混在一起。学习发展史的作用，是看到每一代方法在解决什么问题，又为什么会遇到新的瓶颈。

我用四个问题来记忆每个阶段：

  1. 当时系统主要依靠什么表示知识？
  2. 它如何做出判断或选择动作？
  3. 它解决了上一阶段的什么问题？
  4. 它又留下了什么限制？

二、智能体发展的主线

这条时间线不是严格的单线替代关系。符号规则、机器学习、强化学习、神经网络和大语言模型今天仍然可以组合使用，只是系统的核心能力从“人写规则”逐步转向“模型从数据中学习，再通过工具与环境交互”。

三、第一阶段：符号主义与逻辑推理

早期人工智能研究倾向于把智能理解为符号操作：世界可以被表示为概念、事实、规则和逻辑关系，程序根据这些符号进行推理。

例如，系统可以把知识写成：

这种方法的优点是过程比较清楚：规则是什么、为什么得到结论，都可以被人检查。它适合规则稳定、边界清晰的领域，例如简单的专家诊断、配置检查和流程审批。

但现实世界很难全部写成规则。自然语言存在歧义，知识会不断变化，异常情况数量也会快速增长。规则越多，维护成本越高，规则之间还可能相互冲突。系统能够处理“已经写进规则的世界”，却很难从开放环境中自行获得新知识。

四、第二阶段：专家系统

专家系统把符号主义进一步工程化，通常包含知识库、推理机、工作记忆和解释模块。它试图把领域专家的经验整理成规则，让普通用户可以通过系统获得类似专家的建议。

一个简化的专家系统可以这样理解：

它已经有了 Agent 的一些雏形：读取环境事实，根据规则选择动作或结论。不过它的“智能”主要来自人工编写的知识，面对没有覆盖的情况时只能返回未知。

专家系统带来的启发

  • 知识和执行程序可以分离；
  • 决策过程需要能够解释；
  • 不确定时应该请求更多信息，而不是强行给答案；
  • 规则系统适合承担确定性约束，不能把所有开放问题都交给规则。

这些原则在今天仍然有用。现在的 Agent 也需要工具白名单、权限规则、停止条件和人工审批，这些部分仍然接近传统专家系统的确定性控制。

五、第三阶段：连接主义与神经网络

连接主义把智能看成大量简单单元连接后产生的整体能力。神经网络不再要求工程师为每种输入手写规则，而是通过训练数据调整参数，学习输入与输出之间的关系。

这解决了规则系统难以覆盖感知和语言变化的问题。图像识别、语音识别和自然语言处理都可以从数据中学习模式，而不是把每个像素、音素和句子变成手工规则。

但神经网络也有明显限制：需要大量高质量数据，训练过程可能不稳定，模型内部难以解释，训练好的模型对分布外输入也可能表现很差。它擅长从数据中提取模式，却不天然知道目标、权限、工具和现实世界的后果。

六、第四阶段：机器学习与强化学习

监督学习通常从带标签的数据中学习预测；无监督或自监督学习从数据本身发现表示；强化学习则把问题写成“智能体在环境中观察状态、选择动作、获得奖励、更新策略”。

强化学习和 Agent 的关系尤其重要，因为它直接讨论“如何行动”。游戏、机器人和资源调度等任务都可以用这种交互形式建模。

不过奖励函数很难完整表达真实目标。如果奖励设计不当，系统可能找到投机策略：表面上提高分数，却没有完成我们真正想要的事情。训练成本、探索风险和环境模拟质量也会限制强化学习在开放业务中的使用。

我对强化学习的记忆方式

我把它记成：

现代 Agent 的工具调用、任务规划和多步执行，也常常带有这种“行动—反馈—再行动”的结构，只是很多系统并没有在线训练策略，而是让语言模型在运行时做决策。

七、第五阶段：深度学习和表示学习

深度学习通过更多层的神经网络学习更复杂的表示。卷积网络推动了视觉任务，循环网络和注意力机制推动了序列建模，之后 Transformer 逐渐成为语言模型的核心架构。

表示学习的重要变化是：工程师不必为每个任务手工设计全部特征，模型可以从大规模数据中学习更通用的表示。预训练模型先学习语言或世界中的统计规律，再通过微调、提示词或上下文适配具体任务。

这为后来的大语言模型奠定了基础，但“会生成文本”仍然不等于“能可靠完成任务”。模型还需要外部知识、工具、状态和验证机制，才能从语言生成器变成应用中的 Agent。

八、第六阶段：Transformer 与大语言模型

Transformer 使用注意力机制处理序列中不同位置之间的关系，适合大规模并行训练。随着数据、算力和模型规模增长，大语言模型逐渐表现出文本理解、代码生成、总结、规划和工具调用等能力。

大语言模型给 Agent 带来了三个关键变化：

  1. 自然语言成为通用接口：用户不必学习严格的命令格式；
  2. 模型可以承担开放式决策：根据目标和上下文选择下一步动作；
  3. 同一个模型可以连接不同工具：搜索、数据库、代码、文件和业务 API 都能成为动作空间的一部分。

但大语言模型的知识主要存在参数和上下文中，可能过时、错误或缺少来源。它生成的工具参数也可能不符合要求。因此，现代 Agent 不是“只接一个模型”，而是把模型放在一个可控的系统里。

九、从语言模型到现代 Agent

可以把现代 Agent 看成逐层叠加，而不是一个神秘的新物种：

层次 增加的能力 主要解决的问题
LLM 语言理解和生成 能听懂并组织自然语言
结构化输出 JSON、函数参数和固定格式 让程序能够校验模型结果
工具调用 API、数据库、搜索、代码执行 连接外部世界和实时数据
RAG 检索文档和引用来源 缓解知识过时和事实缺失
记忆 保存用户和任务状态 支持跨轮次和长期任务
工作流 节点、条件、重试和审批 让流程可观察、可测试、可恢复
多 Agent 多个角色分工协作 拆分复杂任务和专业职责

每增加一层能力，也增加一类风险。工具调用增加权限风险，RAG 增加数据和引用问题，记忆增加隐私与错误累积问题，多 Agent 增加通信、成本和调试复杂度。

十、几个容易混淆的概念

Agent 不等于聊天机器人

聊天机器人可以只回答问题；Agent 需要围绕目标执行动作。客服问答如果只是检索并回答，可能不需要复杂 Agent；如果还要查询订单、修改地址、创建工单，就需要工具、权限和状态管理。

Agent 不等于自动化脚本

脚本的流程通常由程序员提前固定；Agent 可以根据输入和中间结果选择路径。二者可以组合：固定的安全边界和数据库写入用代码控制，开放式的意图理解和路径选择交给模型。

多 Agent 不一定优于单 Agent

多个角色会带来分工和复核能力，但也会产生更多调用和通信成本。只有当任务确实存在清晰的角色边界，或者单个 Agent 的上下文和工具空间已经过于复杂时，才值得拆分。

十一、这段历史对我有什么启发

1. 确定性和不确定性应该分开

权限、金额上限、字段格式、最大循环次数和删除操作确认，适合用代码和规则控制。理解用户意图、归纳资料和提出候选方案，可以交给模型。把所有事情都交给模型，或者把所有事情都写成规则，都会失去一部分可靠性或灵活性。

2. 解释能力需要系统配合

专家系统的规则可以解释，大模型的内部推理却不容易直接验证。现代系统可以通过工具调用日志、检索来源、结构化决策、状态快照和评估集，建立“可追踪的解释证据”。解释不是让模型输出一大段思考过程，而是让系统留下可检查的事实。

3. 每一次技术升级都没有消灭旧问题

神经网络减少了手写规则，却带来了数据和可解释性问题；大模型减少了专用模型开发，却带来了幻觉、成本和权限问题；Agent 增加了行动能力，却必须增加安全边界和可恢复机制。

十二、复习提纲

可以用下面这条链路回忆第二章：

复习时可以自己尝试回答下面四个问题：

  1. 为什么规则系统在开放世界中难以扩展？
  2. 强化学习为什么必须关注奖励函数和环境反馈？
  3. 大语言模型为什么需要 RAG、工具和结构化输出？
  4. 为什么现代 Agent 必须有权限、停止条件、日志和评估？

如果能回答这四个问题，基本就抓住了发展史和现代 Agent 之间的联系。

总结

智能体的发展不是从“没有智能”突然跳到“自主 Agent”，而是经历了知识表示、规则推理、数据学习、环境交互、语言建模和工具编排等多次积累。

今天的大语言模型提供了很强的语言理解和决策接口，但它仍然需要传统软件工程提供状态、权限、工具、日志、测试和回滚。理解这段历史后，我对 Agent 的期待也更具体了：它不是替代所有程序的万能大脑，而是一个把模型能力和确定性系统组合起来的执行系统。
